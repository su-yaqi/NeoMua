# users 业务流程

## 核心流程

### 用户修改个人资料

**步骤**
1. 登录用户进入 `/settings`。
2. 前端读取 `/users/me` 展示当前资料。
3. 用户编辑姓名或邮箱后提交。
4. 后端检查邮箱唯一性，通过后更新 `user` 表。

### 用户修改密码

**步骤**
1. 用户在设置页输入当前密码、新密码和确认密码。
2. 后端校验旧密码是否正确。
3. 若新旧密码一致则拒绝更新。
4. 校验通过后更新 `hashed_password`。

### 超级管理员管理平台用户

**步骤**
1. 超级管理员进入 `/admin` 或调用 `/platform/users`。
2. 新建用户时，可在创建阶段附带 `namespace_assignments` 作为初始空间分配。
3. 编辑用户时，仅更新邮箱、姓名、启用状态、密码与 `is_superuser`，不在该表单中维护空间关联。
4. 删除用户时，若目标用户为当前登录超级管理员则拒绝。

## 业务规则

- 邮箱是系统内全局唯一字段。
- 超级管理员不能删除自己。
- 修改密码必须提供正确旧密码，且新密码不能与旧密码相同。
- 平台增强接口中的空间角色来自 `user_namespace_link`。
- 平台用户的空间成员关系应在空间成员管理页维护，而不是在平台用户编辑页维护。

## 数据读写

| 操作 | 表 | 说明 |
|------|-----|------|
| 读 | user | 登录后资料展示、唯一性校验、用户管理 |
| 写 | user | 创建、修改、删除用户 |
| 读 | user_namespace_link | 平台用户回填空间角色 |
| 写 | user_namespace_link | 分配或重置用户的空间角色 |

## 异常场景处理
| 场景 | 处理方式 |
|------|---------|
| 平台用户更新为重复邮箱 | 返回 409 `User with this email already exists` |
| 平台用户创建时邮箱已存在 | 返回 400 |
| 非超级管理员访问平台接口 | 返回 403 |
| 删除自己 | 返回 403 |
