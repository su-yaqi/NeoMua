# llm_configs 业务流程

## 核心流程

### 读取供应商目录

**步骤**
1. 页面进入大模型接入配置页后，请求 `/llm/providers/catalog`。
2. 后端从 `ProviderDefinition` 预置目录组装供应商清单。
3. 前端根据目录动态渲染供应商选择、密钥字段和扩展参数字段。

### 创建空间级接入配置

**步骤**
1. 空间管理员填写配置名称、供应商、接入地址、密钥及可选手工模型。
2. 后端按供应商定义校验必填密钥字段。
3. 密钥载荷被加密为 `secret_ciphertext`，同时生成 `secret_masked` 用于安全展示。
4. 后端写入 `llm_provider_config`，再根据手工模型和启用模型集合初始化 `llm_provider_model`。

### 更新配置并保留历史密钥

**步骤**
1. 管理员进入编辑弹窗修改配置。
2. 若密钥输入留空，前端不提交 `secret_inputs`，后端保留旧密钥。
3. 若提交新密钥，后端重新加密并覆盖已有密文与掩码。
4. 若提交模型变更，则后端以最新手工模型和启用集合重建模型表。

### 连接校验

**步骤**
1. 管理员点击“校验连接”。
2. 后端读取配置并解密密钥载荷。
3. 若供应商支持在线校验，则尝试访问其模型目录或指定探测地址。
4. 成功时更新 `validation_status=success`；失败时写入 `failed` 和脱敏后的错误信息；不支持则返回 `unsupported`。

### 自动同步模型

**步骤**
1. 管理员点击“同步模型”。
2. 后端根据供应商定义判断是否支持模型发现。
3. 支持时调用供应商模型列表接口，得到自动发现模型集。
4. 后端将自动发现模型、已有模型状态、手工模型、启用模型集合合并后重建 `llm_provider_model`。
5. 同步成功时更新校验状态为成功；若远程请求失败，则保留手工模型并记录失败状态。

## 业务规则

- 同一空间内允许维护多条接入配置，也允许同一供应商配置多份不同环境接入。
- `config_name` 在同一 `namespace` 内唯一。
- 配置创建后 `provider_slug` 不可修改，避免字段定义和密钥结构漂移。
- 明文密钥不对外返回，接口仅回传 `secret_masked`。
- 自动发现模型和手工模型可以共存；手工模型可被单独启用或移除。
- 本期不负责默认模型选择，也不负责按这些配置发起真实推理调用。

## 数据读写

| 操作 | 表 | 说明 |
|------|-----|------|
| 读 | namespace / user_namespace_link | 校验当前空间和管理员权限 |
| 读/写 | llm_provider_config | 接入配置新增、更新、校验结果落库 |
| 读/写 | llm_provider_model | 模型清单初始化、同步与启用状态维护 |
| 读 | user | 记录创建人、更新人 |

## 异常场景处理
| 场景 | 处理方式 |
|------|---------|
| 未提供空间上下文 | 返回 400 `namespace_id is required` |
| 非空间管理员访问 | 返回 403 |
| 配置不属于当前空间或不存在 | 返回 404 |
| 缺失供应商必填密钥字段 | 返回 400 |
| 同空间配置名称重复 | 返回数据库唯一约束错误 |
| 供应商不支持在线校验/模型发现 | 返回 `unsupported` 状态，不阻断配置保存 |
