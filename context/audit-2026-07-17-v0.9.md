## 结论

v0.9 已实现 Runtime Node 一对多 Runtime Instance、引擎适配器、稳定模型身份与 Runtime Model Binding、Agent 模型偏好、Activation precheck、Conversation/Workflow 模型模式及 Task 冻结等主体结构。

首次审阅发现的两个 P0、四个 P1 和四类 P2 缺口已按正常执行边界修复，并增加对应负向测试。Runtime 不再相信任务快照自证；无法在当前执行器可靠落实的网络、隔离、CPU、内存、并发或未知策略会在配置应用阶段明确阻断，不会降级或标记为 applied。

## 安全边界说明

- 当前执行器支持 `workspace`/`project` 工作目录策略和 timeout 资源上限。
- `isolated` 工作目录、restricted network、CPU、内存、并发以及未知安全/资源策略尚无可证明的本地执行机制，因此配置应用会返回结构化失败；这属于安全阻断，不是静默降级。
- Runtime 子进程只继承执行必需的安全基础环境；配置中的环境变量必须同时出现在运维级 allowlist，应用内部令牌、数据库凭据和模型认证变量始终排除。
- Runtime capability heartbeat 每 20 秒上报本地事实；能力报告超过 5 分钟或与当前配置不一致时，目录、预检和新任务均拒绝使用旧 Binding。
