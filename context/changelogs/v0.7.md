## 实现内容

- AI 工作台收敛为常见 Chat/Agent 双栏布局：左侧历史会话，右侧历史消息和底部输入区；Workflow 移至独立用户侧菜单。
- 会话创建后固定项目和 Runtime；Chat 模型可切换，Agent 参与者可增减并指定其中一个组织 Agent。配置变更生成不可变修订，每条消息固定实际使用的修订，历史不会被后续修改改写。
- Agent 委派记录改为可展开的完整审计展示，包含 delegation/task 标识、源/目标 Agent、输入、结果或错误。
- 新增大模型未保存草稿的连接校验和模型同步预览；正式保存按请求由服务端重新执行预检并原子持久化，避免留下半成品或信任过期前端结果。
- Agent、Skill、MCP、Plugin、项目和 Spec 标准新增完整创建流程，在一个弹窗或页面中完成必要初始配置；失败整体回滚，不再先创建只有名称与标识的空壳。
- 管理列表的新建入口统一参考 Items 放在页面标题区；用户可见的 Slug 文案统一改为“唯一标识”，API 机器字段保持兼容。
- Workflow 用户侧形成 `/workflows` 应用卡片目录、`/apps/:workflowSlug` 应用切换与实例列表、应用专属新建/详情三级结构；固定版本前端组件缺失时明确阻断，不降级为通用页面。
- Workflow 节点定义和执行逻辑继续固化在代码包；项目及每个可执行节点的 Runtime/Agent 迁移到模板执行配置，并以 CAS 保存为不可变修订。业务实例只填写任务名称和“要做什么”，创建时冻结当前配置修订。
- Workflow 支持模板声明项目必选、可选或禁用；项目实例冻结项目配置，独立实例不伪造项目上下文。
- 新增 `Web 平台开发流` 1.0.1，包含需求沟通、需求设计、技术方案、后端开发、前端开发、测试用例、测试环境部署、测试、人工验收和上线十个节点；详情提供流程步骤、Agent、产出物和聊天页签。
- `project-delivery` 升级至 1.0.6，采用同一模板执行配置模型和简化业务实例创建页。
- 新增四段 Alembic 迁移：会话配置修订、独立 Workflow 上下文、Workflow Agent 角色绑定和模板执行配置。
