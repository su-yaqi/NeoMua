## 实现内容

- 将执行位置与执行引擎拆分为 Runtime Node 和 Runtime Instance。一台 Node 可承载多个 Claude Code、Codex 等 Runtime Instance；项目默认运行时、Skill 同步和 MCP 目标统一指向 Runtime Instance。
- Harness 收敛为 Runtime 内部引擎适配器，不再作为 Agent 下可写的独立配置资源。旧 Harness 与 Runtime Profile 数据仅保留只读历史语义，旧内部能力接口明确返回不可用，不参与新任务执行。
- Runtime Instance 使用不可变配置修订，记录引擎类型、受控配置、配置摘要和应用状态；Node Runtime 按适配器生成确定性启动参数，并按实例报告能力、配置应用和在线状态。
- 新增稳定模型定义、Runtime 模型能力报告与经过验证的模型绑定。只有存在明确 provider/runtime-native 路由且验证通过的模型才可用于执行；模型身份、路由与能力指纹均进入执行证据。
- Agent 草稿与 Release 增加模型偏好和引擎中立执行策略。Release 不绑定 Harness 或具体 Runtime；激活前按目标 Runtime Instance 执行服务器预检，成功后异步部署并生成 Runtime Agent Release。
- Conversation、Agent 组与 Workflow 支持选择具体模型或 `agent_preference`。后者只允许解析为同一稳定模型身份的可用绑定，不进行相似名称、同系列或跨路由替代。
- 项目默认 Runtime、配置修订、Activation 和 Task 均统一使用 Runtime Instance。任务开始前冻结 Runtime、引擎、模型、路由、选择来源和能力指纹；后续配置变化不会改写历史执行。
- 删除旧 Runtime Profile/Harness 的前端写入入口和测试功能，新增 Runtime Instance 列表、实例配置修订、模型能力与绑定管理界面；Developer 保持只读，Admin 才能执行配置与绑定操作。
- 新增三组 Alembic 迁移，完成 v0.9 运行时/模型/执行结构、目标外键和 JSONB/索引元数据对齐。当前旧模型身份回填仍会按 `provider_slug + model_id` 自动建档，尚未满足未知或歧义身份必须阻断并由 Admin 确认的原则。

## 发布阻断项

- P0：Node Runtime 的 `model_evidence` 直接复制服务端任务快照，控制面又与同一快照比较，未证明本地实际 Adapter、配置与模型路由。
- P0：Runtime 配置中的环境白名单、网络策略、资源限制等未在 Worker/Node 执行边界完整应用，却可被标记为 `applied`。
- P1：Node 离线未同步使所属 Runtime Instance 不可用；Runtime 目录和 Activation 预检也未检查连接与能力报告时效。
- P1：模型 Binding 的 `AVAILABLE` 未绑定当前能力指纹、Provider 状态和验证有效期，旧 Binding 可继续出现在目录与预检中。
- P1：迁移会猜测未知/歧义模型身份；绑定 Agent Release 的直接任务仍可覆盖冻结的系统提示词。
- P2：Agent 组无法让同一 Release 承担多个独立角色；逐次模型调用用量协议、精确 compatibility API 和并发 CAS 语义仍不完整。

完整证据、位置和整改门禁见 `context/audit-2026-07-17-v0.9.md`。
