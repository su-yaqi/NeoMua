## 实现内容

- 每个 namespace 自动拥有唯一平台内置 Claude Agent SDK Runtime。其生命周期、配置修订和 Adapter 引用均由系统生成，旧平台创建接口返回 410，配置与 Binding 写入被拒绝。
- LLM 配置会自动映射到平台 Runtime；平台就绪后对每个启用模型执行最小调用，结合 provider 校验时间和 Runtime 能力指纹生成可用 Binding，不以仅拉取模型列表代替具体模型验证。
- service bootstrap 绑定 namespace、模式、设备 Ed25519 公钥和 10 分钟一次性凭证。签名清单固定 Node Manager 与 Claude Agent SDK 版本；service 节点只能上报一个受管 SDK Runtime。
- client bootstrap 不携带 Claude Agent SDK，签名 Adapter Registry 当前支持本机 Claude Code 与 Codex。管理端只检查 Adapter 声明的有限绝对候选，不读取用户 Shell、不扫描目录、不使用 PATH 猜测；同引擎多个安装分别保存稳定本地 UUID，并使用精确绝对路径、文件指纹、身份、版本与本地登录证据执行。
- Node Manager 基础包不再强制依赖 SDK，`service` extra 与平台 worker 镜像显式安装 `claude-agent-sdk==0.2.110`。锁文件和两套 Docker 构建已验证依赖边界。
- 安装器要求 HTTPS、Linux/systemd 和支持的架构，验证签名清单与精确组件版本；身份/配置通过 staging 成对原子落盘，systemd unit 使用受限绝对路径。仅注册响应发生传输中断时允许同设备证明恢复，普通冲突不触发恢复。
- service Runtime 复用已完成最小真实调用的 Provider 模型验证，自动生成绑定自身能力指纹的精确 Gateway Binding；没有可用模型时保持不可执行，不伪装成可用。
- Runtime 管理页移除平台 Runtime 创建、命令配置和手工模型 Binding，按平台内置/服务节点/客户端/历史分组；Admin 可生成 service/client 安装凭证、查看 bootstrap/receipt/发现代次与诊断、请求受控重扫，并审计式暂停或恢复受管节点的新任务调度。
- 大模型配置页把连接探活、模型级真实调用、协调任务、Worker 发行信任和最终 Binding 就绪状态放在同一流程展示。
- v0.10 迁移可识别开发期同 revision 的部分已应用字段并增量补齐，不需要删库；Runtime Worker 在清理 Agent 子进程环境前消费并移除自身发行摘要，避免凭证清理误伤启动配置。

## 运维约束

- 正式节点安装仅支持 Linux/systemd 和 HTTPS 平台地址；不支持的主机明确失败，不切换到其他运行方式。
- client 当前签名 Registry 仅包含 Claude Code 与 Codex；新增其他引擎必须随受签名 Registry 和对应受测 Adapter 发布，未知可执行文件不会被执行。
- 本地测试环境仍使用模板弱密钥并产生既有警告；生产环境必须注入独立强密钥。

## 工程环境收口（2026-07-29）
