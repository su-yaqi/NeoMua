# v0.2 变更记录

## 基本信息
- 完成时间：2026-06-11
- 对应 PRD：`context/prds/v0.2/`

## 实现内容

### namespaces
- 前端新增空间成员管理页 `/system/namespaces/:namespaceId/members`，形成空间成员增删改闭环。
- 空间列表页新增“成员管理”入口；父级路由补齐 `Outlet`，保证子路由可渲染。
- 左侧导航新增独立“空间成员管理”入口，默认指向当前 `selected_namespace_id`。
- 非 `superuser` 的空间管理员不能移除自己，也不能把自己从 `admin` 降级。

### users
- 平台用户创建支持初始空间分配。
- 平台用户列表不再展示空间角色摘要。
- 平台用户编辑弹窗不再维护空间关联，只保留基础资料、状态和全局角色编辑。
- 平台用户更新时，重复邮箱场景改为明确返回 `409`，不再出现 `500`。

### auth / testing
- `private` 调试接口支持创建 `is_superuser`、`is_active` 可控的测试用户。
- Playwright 的登录、设置、平台治理测试全部改为使用临时用户或临时 `superuser`。
- 固定开发账号 `admin@example.com / changethis` 已从前端测试链路中移除，仅保留给人工联调。

## PRD 一致性校验结果

| PRD 要求 | 实际实现 | 偏差原因 | 处理决策 |
|---------|---------|---------|---------|
| 空间成员管理形成前端闭环 | 已完成 | 无 | 已完成 |
| 平台用户可在创建阶段设置空间分配 | 已完成 | 无 | 已完成 |
| 平台用户管理展示空间摘要并在编辑页维护空间关联 | 已调整为仅创建阶段设置，编辑阶段移至空间成员页维护 | 基于产品迭代要求收敛交互 | 以当前实现为准，文档同步修正 |
| 固定超级管理员可作为长期稳定测试账号 | 已取消该依赖 | 固定账号会随本地数据库漂移 | 改为测试期间临时创建用户 |

## 遗留问题

- 本地开发数据库中的 `admin@example.com / changethis` 仍可能因数据库重建或切换而丢失；该问题已从测试链路中隔离，但人工联调仍受影响。
- 左侧“空间成员管理”入口当前按是否存在 `selected_namespace_id` 展示，最终细粒度显示策略仍以后端权限为准。
- 平台用户创建阶段仍支持设置初始空间关联，如后续产品希望完全统一入口，可再收敛到空间成员管理页。
